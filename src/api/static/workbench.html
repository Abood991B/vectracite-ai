Retrieval accuracy

How well does the studio find the right evidence?

Three retrieval stages are measured on the active corpus. The rank table explains each query in plain English, not just as a score.

Metric guide

Precision@1How often the first result is the exact page we expected.
Recall@3How often the expected page appears somewhere in the first three results.
MRRMean reciprocal rank: 1.00 means rank one, 0.50 means rank two, and 0.00 means it was not found.
nDCG@3Discounted rank quality: a correct result at rank one scores 1.00, with lower credit for ranks two or three.
Mean latencyAverage CPU time for one query after model warmup.
Score scale: 0.00 = no correct result · 1.00 = correct result at rank one

LLM & API setup

Optional OpenAI-compatible answer synthesis

Runs locally for free: PyMuPDF parsing, BAAI/bge-small-en-v1.5 embeddings, BAAI/bge-reranker-base scoring, and DeterministicNumericVerifier checks. An optional OpenAI-compatible provider can synthesize answers when enabled. Only the question and retrieved evidence text leave the host; raw PDF bytes stay local. The deterministic path remains the default and the automatic fallback on provider failure.

The key is held in this API process's memory, never written to disk, and cleared on restart. The base URL must point at an OpenAI-compatible /v1 endpoint.
